# AGENTS.md

## Purpose

This repository contains the source for [Mark's Math](https://marksmath.org/), a Quarto website with course materials, mathematical visualizations, writing, presentations, data notes, and shared site components.

This file gives AI coding agents enough context to make useful, careful changes without damaging generated output or site conventions.

## Repository Overview

- Quarto website project configured by `_quarto.yml`
- Main content written in `.qmd` files
- Site sections include:
  - `classes/` — course pages, syllabi, calendars, notes, handouts, demos
  - `visualization/` — math, classroom, and data visualizations
  - `writ/` — essays, reports, and longer-form writing
  - `scholarship/` — scholarly materials, including papers in `scholarship/papers/`
  - `presentations/` — presentation-related pages
  - `data/` — data-oriented pages and supporting files
  - `carousel/` — standalone JavaScript slide demos used by the home page
  - `OfficialPolicies/` — a standalone page of official UNCA student information
  - `components/`, `jslib/`, `styles/` — shared JavaScript, CSS, includes, and reusable assets
  - `scripts/` — Node.js build scripts (figure export and the pre-render hook)
  - `_extensions/` — vendored Quarto extensions (`qmd-lab/closeread` for scrollytelling, `tomicapretto/carousel`); treat as third-party code and do not casually edit

## Important Files and Directories

- `_quarto.yml` — global Quarto website configuration
- `README.md` — public project overview, plus full documentation of the figure-export workflow and the Mapbox token strategy
- `styles/main-styles.css` — global site styling (set in `_quarto.yml`); `styles/sage-styles.css` is loaded by pages with Sage-based interactive content
- `mathjax-config.html` — MathJax configuration included in HTML output
- `components/includes/latex-macros.html` and `latex-macros.tex` — shared LaTeX macros available across documents; check them before defining new notation
- `scripts/pre-render-figures.cjs` — pre-render hook (declared in `_quarto.yml`) that regenerates PDF figures from saved SVGs for opted-in documents
- `scripts/export-figures.cjs` — exports OJS/SVG figures as vector PDFs for printed handouts (requires Chrome and Playwright)
- `_environment` — committed environment file holding the deployment-scoped Mapbox token; `_environment-devel` (gitignored) holds the unrestricted development token
- `_axe-checks/` — disposable axe accessibility scan artifacts, regenerated by `quarto call axe`; never edit by hand
- `_site/` — generated website output; never committed, never edited by hand
- `_freeze/` and `.quarto/` — Quarto cache/freeze/build metadata; avoid unnecessary edits

## Local Development

Common commands:

```sh
quarto preview       # interactive preview
quarto render        # full site build
quarto render PATH   # render a single document — much faster on a site this size
```

### Toolchain

- Quarto — use a recent version; extensions and the axe scanner may require one (scan artifacts were last generated with Quarto 1.11.9)
- Node.js — needed by the scripts in `scripts/`
- Google Chrome and Playwright (`npm install --no-save playwright`) — needed only for figure export
- Python/Jupyter (and R for some pages) — needed to execute code chunks in `.qmd` files

`_quarto.yml` sets `execute: freeze: auto`, so previously rendered pages re-render from the `_freeze/` cache without a full language environment. New or changed computations, however, need the relevant kernel installed.

### Figure export for PDF handouts

Many class handouts are built for both web and print. Each figure appears twice — an OJS/SVG version shown on the web and a PDF image used in the printed handout — inside `content-visible` blocks sharing the same `fig-` label:

````markdown
::: {.content-visible when-format="html"}
```{ojs}
//| label: fig-example
//| fig-cap: "An example plot."
Plot.plot({...})
```
:::

::: {.content-visible when-format="pdf"}
![An example plot.](figures/example.pdf){#fig-example fig-alt="Description of the plot."}
:::
````

- Documents opt in with `export-svg-figures: true` in their top-level YAML, which runs the pre-render hook to regenerate figure PDFs from saved SVGs.
- After changing OJS plots, refresh the saved SVGs by running `node scripts/export-figures.cjs` against a running preview.
- Keep the two halves paired: matching `fig-` labels, and never delete or rename one half without the other.

The README documents this workflow in full, including its limitations (SVG figures only, explicit dimensions required).

### Accessibility

Accessibility is a real requirement here: PDF output targets PDF/UA-2 (`pdf-standard: ua-2` in `_quarto.yml`), and the rendered site is checked with `quarto call axe`.

- `_axe-checks/` holds scan artifacts — regenerated on every scan, never edited by hand.
- Accepted findings are recorded by hand in `_axe-baseline.json` at the repo root (create it as `{ "findings": [] }` if absent), with a note explaining each decision.
- `_axe-checks/README.md` documents the full workflow; read it before touching any accessibility output.
- Fixes go in the Quarto source (`.qmd`, `_quarto.yml`, theme files), never in `_site/`.

## Editing Guidelines

- Prefer small, focused changes.
- Preserve existing Quarto structure and naming patterns.
- Keep mathematical notation in standard LaTeX syntax, and check the shared macros in `components/includes/` before defining new commands.
- Avoid hand-editing generated output in `_site/` and scan artifacts in `_axe-checks/`.
- Do not disturb frozen computations unless the task requires it.
- When editing course materials, preserve dates, course names, and pedagogical intent unless explicitly asked to update them.
- When editing visualizations, check both the `.qmd` source and any linked JavaScript/CSS assets.

### Private, unversioned course content

`.gitignore` deliberately keeps certain course material out of version control: `classes/*/_exams_and_quizzes/`, `classes/*/_quizzes_and_exams/`, `classes/*/MyOpenMath.qmd`, `classes/*/_courseData/`, and scratch notebooks. These exist locally but are intentionally untracked. Never publish, link to, or copy this material into public pages.

## Quarto Conventions

Document pages generally use:

- YAML front matter where needed
- Markdown prose
- LaTeX math
- Executable code chunks when appropriate
- Embedded JavaScript or Observable-style content for interactive pieces

Global site behavior comes from `_quarto.yml`, including themes, MathJax setup, page layout, navbar links, footer, resources, and execution freeze behavior.

## Content Areas

### Classes

Each course section gets one directory per semester, named `classes/<Term><Year><Course>/` — for example `classes/Fall2026CalcI/` or `classes/Spring2026MML/`. Directories contain notes, syllabi, calendars, handouts, demos, and reusable course components; the demos are often interactive JavaScript visualizations, as described in the next section.

- **Old classes are archived on purpose.** Past semesters stay in `classes/` indefinitely, listed by semester heading in `classes/index.qmd` (older classes remain at legacy.marksmath.org). Never prune, "clean up," or overwrite old class directories.
- **A new semester means new directories**, not edits to old ones.
- **Current classes live on the home page** (`index.qmd`) under the current semester heading. At each semester transition, the finished classes move into the `classes/index.qmd` listing and the new ones are added to the home page. Don't reorganize these listings unless asked.
- When a task refers to a course without naming a semester, the "current" class is the most recent semester's directory — check the home page or the newest directory names.

### Visualizations

The `visualization` directory contains mathematical and data visualizations that might be used in classes but are often shared more broadly. These are broken into

- `visualization/data/*` contains pure data visualizations
  - for example `visualization/data/NCAABrackets/` provides NCAA bracket visualization dating back to 1984.
- `visualization/math/*` contains advanced mathematical visualizations of general interest
  - for example, `visualization/math/JuliaSetsAndMandelbrotSet` provides an interactive look at Julia sets and the Mandelbrot set
- `visualization/class/` contains class specific visualizations that I might refer to frequently across multiple classes
  - for example, `visualization/class/unit_circle` provides an interactive look at the unit circle.

Generally, these directories contain
  - QMD files to describe the visualizations in Quarto based markdown. These files frequently use `ojs` code blocks to coordinate Javascript visualizations written in Observable flavored Javascript.
  - JS files to generate the pure javascript visualizations.
  - CSV or JSON data files to store any data we'd like to visualize.
  - IPython notebooks used for processing raw data to a form more palatable form for Javascript.

### Writing

The `writ/` directory contains my own writing on various subjects. Often, these writings are accompanied by visualizations, as in the previous section on visualization.

### Data

The `data` directory contains raw data, largely for sharing.

## Working practices

### Secrets and External Services

- Do not commit secrets, private API keys, or unrestricted tokens.
- Mapbox maps use a two-token scheme: the committed `_environment` file holds the deployment-scoped public token, and the gitignored `_environment-devel` holds the unrestricted development token. The README's "Mapbox Tokens" section describes the setup.
- Check existing environment conventions before adding new service dependencies.

### Deployment

There is no CI/CD configuration in this repository, and `_site/` is gitignored — rendered output is never committed. Do not commit build output or generated artifacts; if a task seems to require touching the publish process, ask first.

### Validation Checklist

Before finishing a change, consider:

- Does the edited `.qmd` render?
- Are links still valid?
- Does math display correctly?
- Do visualizations load required JS/CSS/assets?
- If the page uses paired HTML/PDF figures, do both halves still work (the web figure and the printed PDF)?
- For handouts, is the PDF still accessible (PDF/UA)?
- Did the change introduce accessibility regressions? A one-page `quarto call axe` rescan can check.
- Did any generated files change unintentionally?
- Is the change scoped to source files rather than build output?

### Agent-Specific Instructions

AI agents working in this repo should:

- Read nearby files before making stylistic changes.
- Match existing tone, structure, and formatting.
- Prefer Quarto-native solutions over custom HTML/JS when Quarto already supports the feature.
- Keep generated/cache directories out of ordinary edits.
- Explain any broad changes before making them.
- Flag uncertainty around course policies, assignment dates, grading language, or public-facing claims.
- Never modify archived class content unless the task explicitly asks for it.
