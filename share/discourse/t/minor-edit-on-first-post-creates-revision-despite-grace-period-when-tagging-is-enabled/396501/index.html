Minor edit on first post creates revision despite grace period when tagging is enabled

Moin

Steps to reproduce:

  1. Check site settings:
    • Ensure Tagging enabled is enabled
    • Ensure Editing grace period is long enough so you can perform a minor edit within that timespan
  2. Create a new topic with some content and publish it
    image871×475 24.7 KB
  3. Delete one word from the topic (in my case, I deleted the last word) and save the edit
    image787×473 24.4 KB

Expected result: No edit revision is created because this is a minor change made within the editing grace period.
Actual result: A hidden post revision is created (you can see the orange pencil icon in the screenshot above)

Why this seems to be related to tagging (even though no tag was involved):

  1. If you perform the same steps in a reply instead of the first post, no revision is created. So the Editing grace period and the fact that the change is minor do not seem to be the issue.
  2. If you perform the same steps on a first post while Tagging enabled is disabled, no revision is created either.

This makes me think the issue is somehow related to tagging, even though the created topic had no tags and the edit did not add or modify any tags.

FIX: Prevent unnecessary revision when editing first post with tagging enabled (#37989)

main ← fix-tag-revisions
merged 04:59PM - 23 Feb 26 UTC
janzenisaac
+49 -14

When editing the first post of a topic, we send `tags: []` via `PUT /t/:id` even… when the topic has no tags. Since `[].present?` is `false`, the existing tag cleanup logic was skipped, leaving a no-op tags key in the changes hash. This caused `PostRevisor#topic_changed?` to return `true` (it checks key presence, not value), bypassing the grace period and creating an empty hidden revision. To fix this I updated the condition in `TopicsController#update` to use `has_key?` instead of `present?`, and delete the tags key when both the incoming tags and existing tags are empty. Also added matching normalization in `PostRevisor#revise!`
